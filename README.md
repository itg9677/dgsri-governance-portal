# بوابة الحوكمة والأداء المؤسسي — عمادة الدراسات العليا والبحث العلمي (DGSRI)

واجهة ويب ثابتة (HTML/CSS/JavaScript بدون أدوات بناء) تتصل بقاعدة بيانات **Supabase** (PostgreSQL + Auth + Storage).
الأدوار: **منسق وحدة** (يدخل القياس ويرفع الدليل) · **وكيل** (يعتمد/يعيد ويعدّل المستهدف لوكالته) · **عميد** (يرى الكل ويعتمد للوحدات المرتبطة به ويدير الفترات).

**ترتيب تحميل ملفات JS مهم** (محدد في `index.html`): الإعدادات ← API ← النواة ← المكوّنات ← الخدمات ← الصفحات ← الهيكل ← main. الملفات سكربتات عادية تشترك في نطاق واحد (بدون import)، فلا تغيّر الترتيب ولا تضف ملفًا جديدًا إلا بإضافته في `index.html`.

## أين أعدّل؟
| أريد تعديل... | الملف |
|---|---|
| نص ثابت أو اسم حالة أو نوع ربط | `core/constants.js` |
| معادلة النتيجة أو المستهدف أو من يعتمد | `core/logic.js` + الدوال في `supabase/01_schema.sql` |
| شكل بطاقة مؤشر | `components/kpi-card.js` + `css/components.css` |
| نافذة تفاصيل المؤشر | `components/kpi-modal.js` + `css/pages.css` |
| صفحة معينة | `pages/<اسم الصفحة>.js` |
| القائمة الجانبية أو الترويسة | `layout/shell.js` + `css/layout.css` |
| استدعاء جديد لقاعدة البيانات | `services/api.js` ثم `services/live-data.js` |
| الألوان والخطوط | أول `css/base.css` (`:root`) |

> الصلاحيات الحقيقية تُفرض في قاعدة البيانات (RLS والدوال). ما تخفيه الواجهة أو تُظهره هو للتسهيل فقط، وليس للأمان.

## التشغيل لأول مرة
1. **Supabase**: أنشئ مشروعًا، ثم في SQL Editor شغّل `supabase/01_schema.sql` ثم `02_seed.sql` (لا تشغّل `01` مرتين).
2. **المستخدمون**: Authentication ← Users ← Add user (فعّل Auto Confirm). انسخ UUID كل مستخدم وعدّل `03_profiles_template.sql` ثم شغّله. المستخدم بدون صف في `profiles` لا يرى شيئًا.
3. **إيقاف التسجيل الذاتي**: Authentication ← Sign In / Providers ← عطّل Allow new users to sign up.
4. **المفاتيح**: Project Settings ← API، وضع Project URL والمفتاح العام (anon/publishable) في `web/js/config/supabase-config.js`. **لا تضع service_role أبدًا.**
5. **تجربة محلية**: افتح مجلد `web` في VS Code وشغّل `index.html` بإضافة Live Server، وادخل ببريد أحد المستخدمين.
6. **قبل الإطلاق**: عبّئ أسماء المؤشرات وأكواد الخطة (`update public.kpis set name_ar=..., plan_code=... where code=...`) واحذف المستخدمين التجريبيين.

## الرفع على GitHub والنشر
- ارفع المجلد كاملًا إلى مستودع (يفضّل **Private**). مفتاح anon مصمم ليكون علنيًا ومحميًا بـ RLS، لكن لا ترفع أي مفتاح سري.
- النشر: المجلد المنشور هو `web/` فقط.
  - **Netlify / Cloudflare Pages / Vercel**: اختر Publish directory = `web` بلا أمر بناء.
  - **GitHub Pages**: لا يسمح إلا بالجذر أو مجلد `docs`، فإما تنشر عبر GitHub Actions من مجلد `web`، أو تعيد تسمية `web` إلى `docs`.
- بعد النشر ضع رابط الموقع في Supabase ← Authentication ← URL Configuration.

## ما هو مربوط وما لا
مربوط بقاعدة البيانات: الدخول والخروج، قراءة الوكالات والكيانات والمؤشرات والفترات والمستهدفات والقياسات والتدقيق، إدخال القياس ورفع الدليل، تنزيل الدليل (رابط مؤقت)، الاعتماد والإعادة (فردي وجماعي)، تعديل المستهدف (من الفترة الحالية فصاعدًا)، إقفال الفترات وفتحها.
غير مربوط بعد: السجلات التفصيلية (`register-modal.js`)، اللجان (قائمة ثابتة)، التقارير، وجدول الإشعارات (الجرس يُحسب من حالة القياسات).
إقفال الفترة: الواجهة تمنعه مع وجود سجلات غير منشورة، لكن الدالة في القاعدة لا تتحقق من ذلك بعد.
